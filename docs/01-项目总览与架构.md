# 01 · 项目总览与架构

## 1. 产品定位

「AI 提瓦特向导」是一个面向《原神》玩家的智能助手工具站，核心能力：

1. **智能问答**：角色配队、圣遗物选择、养成优先级、活动攻略等。
2. **图鉴速查**：角色 / 武器 / 材料结构化检索（预留）。
3. **路线规划**：按目标生成采集 / 刷本路线（预留）。

## 2. 技术选型

| 层 | 技术 | 理由 |
| --- | --- | --- |
| 视图 | React 19 + TypeScript | 生态成熟、类型安全 |
| 构建 | Vite 7 | 冷启动快，配置简单 |
| 样式 | Tailwind CSS 4 | CSS-first 主题，无需额外配置文件 |
| 状态 | Zustand 5 | 轻量，无 Provider 样板代码 |
| 路由 | React Router 7 | 官方主流方案 |
| 动画 | framer-motion | 交互过渡（按需使用） |
| 图标 | lucide-react | 树摇友好 |
| 后端框架 | Gin | 高性能、生态完善 |
| 数据库 | MySQL 8.4（本地 127.0.0.1:3306） | 已有环境，启动时自动建库建表 |
| ORM | GORM（MySQL / SQLite 可切换） | 换驱动只改配置，不改业务代码 |
| 配置 | Viper | yaml + 环境变量覆盖 |
| 日志 | Zap | 结构化、高性能 |
| 鉴权 | JWT v5 | 无状态登录 |
| 模型 | go-openai（OpenAI 兼容协议） | 可对接多家兼容厂商 |

## 4. 分层职责

| 层 | 目录 | 职责 | 禁止 |
| --- | --- | --- | --- |
| Router | `internal/router` | 路由与中间件装配 | 写业务逻辑 |
| Handler | `internal/handler` | 参数绑定、调用 service、封装响应 | 直接操作 DB |
| Service | `internal/service` | 业务编排、事务边界、外部调用 | 感知 HTTP 细节 |
| Repository | `internal/repository` | 数据读写封装 | 写业务规则 |
| Model | `internal/model` | 数据表结构 | 含业务逻辑 |
| DTO | `internal/dto` | 出入参结构 | 与 model 混用 |
| Pkg | `internal/pkg` | 日志 / 响应 / 数据库等基础设施 | 依赖上层 |

## 5. 数据流（以对话为例）

1. 用户在 `ChatInput` 输入 → `useChatStore.sendMessage()`
2. Store 立刻插入用户消息 + 一条 `pending` 占位消息（乐观更新）
3. `api/chat.ts` 调用 `POST /api/chat`
4. Vite 代理转发到 Gin → `ChatHandler` → `ChatService.Ask`
5. Service 落库历史 → 调 `AIClient.Complete` → 落库回复
6. 返回 `{ code, message, data }`，Store 替换占位消息完成渲染

## 6. 约定

- 所有后端响应统一为 `{ code, message, data }`，`code === 0` 视为成功。
- 前端接口层统一拆箱，页面只关心业务数据。
- 时间字段统一 RFC3339；金额/数值不做隐式单位转换。
- 配置优先：环境变量 > `config/config.yaml` > 代码默认值。
